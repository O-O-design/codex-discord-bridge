# Codex Discord Bridge

Run a local Codex CLI session behind an allowlisted Discord bot.

This is not an OpenAI API chatbot. The Discord bot only receives and sends
messages. The reply is generated by a local Codex CLI session on your machine.

```text
Discord allowlisted channel
  -> discord.js bridge
  -> local Codex CLI session
  -> Discord reply
```

## Features

- Discord guild/channel/thread allowlists.
- Optional channel/thread denylists.
- Local Codex CLI session resume.
- Per-user sandbox gate: trusted users can use `CODEX_SANDBOX`; everyone else
  is forced to `read-only`.
- Optional Discord reply-reference context.
- Optional recent message context with a strict limit.
- AI-bot loop guard to prevent infinite bot-to-bot chatter.
- Local runtime monitor at `http://127.0.0.1:3899`.
- Compact bridge status widget at `http://127.0.0.1:3899/widget`.
- macOS Swift/WebKit widget wrapper.
- Windows PowerShell launchers.
- Codex CLI stdout/stderr activity events for real background status.

## Requirements

- Node.js 22.12 or newer.
- Discord bot token with the required guild/message intents.
- Codex CLI installed and signed in locally.

Default Codex CLI path:

- macOS: `/Applications/Codex.app/Contents/Resources/codex`
- Windows/Linux: `codex` from `PATH`

Set `CODEX_CLI_PATH` in `.env` if your install is elsewhere.

## Setup

```sh
npm install
cp .env.example .env
```

Fill in `.env`:

```text
DISCORD_TOKEN=
DISCORD_CLIENT_ID=
DISCORD_GUILD_IDS=
DISCORD_CHANNEL_IDS=
```

At least one of these must be configured:

```text
DISCORD_CHANNEL_IDS
DISCORD_PARENT_CHANNEL_IDS
DISCORD_THREAD_IDS
```

Then seed the Codex session:

```sh
npm run seed
```

The session id is stored in `state/codex-session`.

## Run

```sh
npm start
```

In another terminal:

```sh
npm run monitor
```

Open:

```text
http://127.0.0.1:3899
http://127.0.0.1:3899/widget
```

## Customize

The public defaults are intentionally generic. For a personal bridge, edit only
the small surface below first:

```text
.env
memory/default-seed.md or your private CODEX_SEED_FILE
src/monitor.js
```

Recommended customization points:

- Bot identity and Discord allowlists: edit `.env`.
- Personal Codex behavior or relationship context: create a private seed file
  and set `CODEX_SEED_FILE=memory/your-private-seed.md` in `.env`.
- Widget title, badge, and visible labels: edit the widget HTML near
  `widget-badge`, `widget-kicker`, and `widget-title` in `src/monitor.js`.
- Widget colors and spacing: edit the CSS variables near the top of
  `src/monitor.js`, plus the widget-only CSS block around `body.widget`.
- Public/open-source naming: keep the README and default seed generic, then put
  private names, server ids, and personal prompts in ignored local files.

Do not commit `.env`, private seeds, tokens, personal server ids, or member
rosters.

## Configuration

- `DISCORD_TOKEN`: Discord bot token.
- `DISCORD_CLIENT_ID`: Discord application/client id.
- `DISCORD_GUILD_IDS`: allowed guild ids, comma-separated.
- `DISCORD_CHANNEL_IDS`: allowed text channel ids, comma-separated.
- `DISCORD_PARENT_CHANNEL_IDS`: allowed parent/forum channel ids whose threads
  may be read, comma-separated.
- `DISCORD_THREAD_IDS`: allowed thread ids, comma-separated.
- `DISCORD_BLOCKED_CHANNEL_IDS`: denied channel/thread ids.
- `DISCORD_BLOCKED_PARENT_CHANNEL_IDS`: denied parent/forum ids.
- `DISCORD_ALLOWED_BOT_AUTHOR_IDS`: bot users allowed to trigger Codex.
- `DISCORD_WRITE_USER_IDS`: users allowed to run `CODEX_SANDBOX`; everyone else
  is read-only.
- `CODEX_CLI_PATH`: optional Codex CLI path.
- `CODEX_SESSION_FILE`: default `state/codex-session`.
- `CODEX_SEED_FILE`: default `memory/default-seed.md`.
- `CODEX_SANDBOX`: `read-only`, `workspace-write`, or `danger-full-access`.
- `CODEX_TIMEOUT_MS`: per-Codex-call timeout.
- `DISCORD_BATCH_WINDOW_MS`: short-message batching window.
- `DISCORD_CONTEXT_LIMIT`: optional recent-channel context limit. `0` disables
  this.
- `DISCORD_BOT_LOOP_MAX_TURNS`: bot-to-bot loop max turns.
- `DISCORD_BOT_LOOP_WINDOW_MS`: bot-to-bot loop time window.
- `DISCORD_BOT_LOOP_COOLDOWN_MS`: cooldown after loop limit.
- `BRIDGE_LOG_FILE`: local runtime log file.
- `BRIDGE_LOG_MESSAGE_LIMIT`: max text excerpt length in logs.
- `MONITOR_PORT`: local monitor port.
- `MEMBER_ROSTER_FILE`: optional private CSV roster path.

## Runtime Monitor

The monitor reads the local runtime log only. It does not modify Discord or the
Codex session.

The widget history hides engineering internals such as job ids and sandbox
names. It shows readable status like:

```text
已回覆 Discord
1 則訊息 · 耗時 12 秒
```

Codex CLI stdout/stderr chunks are logged as `codex_cli_output`. The widget may
show a real generic state such as `Codex 有新的執行輸出`. It does not claim
specific tools such as web search or image generation unless a stable Codex CLI
event format has been confirmed.

Use the probe script to inspect available stream signals:

```sh
npm run probe:codex-stream -- "Reply with one short sentence."
```

See [docs/CODEX_STREAM_PROBE.md](docs/CODEX_STREAM_PROBE.md).

- `logs/`
